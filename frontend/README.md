# Интерфейс EduProject · Sprint 1

HTML/CSS/JavaScript с локальным CSS Bootstrap 5.3.3. Сборка и npm-зависимости для запуска не нужны. `index.html` и `assets/` отдаёт FastAPI на том же origin, что и `/api/v1`.

Реализованы вход/выход, список и создание проектов, сведения проекта, доска и создание задач, карточка задачи, назначение/смена/снятие исполнителя, начало выполнения, состав команды, создание и отзыв приглашений, публичное приглашение и принятие после входа. Поздние стадии доски отображают реальные данные, но не предлагают не реализованные действия сдачи/проверки.

Фронтенд не содержит демонстрационного входа, пользователей, задач или fallback-данных. Тестовые ответы есть только в `tests/`. Сессия и CSRF читаются через `GET /api/v1/auth/session`; запросы используют cookie, изменения — CSRF, изменения задачи — ETag/If-Match последнего чтения. Секреты и токены не записываются в localStorage или журналы. Ссылка приглашения показывается только в ответе создания; её нельзя восстановить из списка.

Перед переходом в Telegram интерфейс проверяет `GET /api/v1/auth/configuration` → `{telegram_login_configured: bool}`. Если вход ещё не настроен, пользователь получает сообщение на странице. Когда настроен — браузер переходит на обычный OIDC endpoint, без подмены проверки личности.

## Проверка

Проверено 1 ноября 2026: **31/31 Node-тест, 8/8 проверок HTTP-контракта FastAPI, 2/2 проверки синтаксиса JS прошли**. Фактические числа и время запуска сохранены в `testresult.json`; первичные результаты — в `tests/results/`. Проверки логики запускают настоящий `app.js` в минимальном DOM-окружении с тестовыми ответами, а HTTP-проверки читают реальные FastAPI-маршруты через TestClient. В том числе проверены обработка истёкшей сессии при работе с формой или карточкой задачи и дополнительный заголовок API-запросов только на доменах Pinggy. Изменения не повторяются автоматически после ошибки.

В папке `frontend`: `npm test` (Node.js 20+). Полный повтор с обновлением `testresult.json`: `npm run check`. Для HTTP-проверок нужен `backend/.venv` с установленными backend-зависимостями. Дополнительно: `node --check assets/app.js` и `node --check assets/api.js`.

HTTP-проверки проверили выдачу HTML, локальных JS/CSS и Bootstrap, соответствие CSP без `unsafe-inline`, SPA-маршруты, ответ флага настройки Telegram, честный 503 при отсутствии настройки входа, 401 для анонимной сессии/проектов/выхода, а также методы/поля задач в текущем OpenAPI. Эти проверки не подключают Telegram, не создают рабочую сессию и не проверяют сохранение данных в PostgreSQL. Windows sandbox блокирует внутренний event-loop/socketpair TestClient; успешный локальный запуск выполнен с разрешением на эту проверку, без внешней HTTP-сети.

## Визуальная и сквозная приёмка

Нужен запущенный backend с миграциями PostgreSQL. Открывать через HTTP(S) приложения, не через `file://`. Исторические маршруты `/login`, `/projects`, `/projects/{id}`, `/invitations/{token}` должны возвращать `index.html`.

1. При выключенном Telegram открыть `/login`, нажать «Войти через Telegram»: должно остаться понятное сообщение, сессия не создаётся. При недоступном сервере — сообщение и повтор загрузки.
2. В настоящей сессии проверить пустой список проектов; создать проект с обязательными полями. Пустые/состоящие из пробелов поля не отправляются. Срок переводится из времени устройства в UTC с явным `Z`.
3. В проекте открыть «Команда», создать ссылку, скопировать её. Открыть её в другом профиле браузера, выполнить настоящий вход и присоединиться. Повторное принятие не меняет роль. Отозванная ссылка недоступна.
4. Создать задачу, назначить участника. В его сессии открыть карточку и «Начать выполнение». Проверить новую колонку после обновления страницы и перезапуска сервера. Другой участник не видит кнопку начала.
5. В двух окнах открыть карточку задачи. В первом изменить исполнителя, во втором сохранить старую версию: понятная ошибка конфликта с кнопкой «Обновить задачу», без автоматического повторения изменения.
6. Проверить реальную пагинацию на более чем 100 задачах: доска запрашивает все страницы. Для списка проектов проверить страницы по 12 записей.
7. На desktop 1440×1024 и mobile 390×844 проверить `/login`, пустой/заполненный список, доску, команду, сведения, формы и приглашение. На mobile доска прокручивается горизонтально; содержимое страницы и формы не должно выходить за ширину экрана. Проверить Tab/Shift+Tab, Escape в диалоге, возврат фокуса и сообщения ошибок.

Подтверждение и границы этой проверки сохранены в `../docs/LOCAL_VERIFICATION.json`. Она не входит в автоматические HTTP-проверки и не подтверждает совместную работу двух участников команды.

Проверены публичный просмотр приглашения, вступление второго QA-пользователя, повторное принятие без дублирования участника и недоступность отозванной ссылки. Временный внешний адрес сейчас недоступен; постоянная поставка и полная независимая приёмка AC ещё не выполнены. Настоящий публичный прогон не использовал тестовую аутентификацию и не изменял код приложения.

Ручные проверки мобильного интерфейса, управления клавиатурой, конфликта ETag в двух окнах и пагинации на большом наборе данных ещё не выполнены. Список выше сохраняется для дальнейшей приёмки; наличие пункта в нём не означает успешное прохождение.
