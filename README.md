# EduProject — первый программный инкремент

Учебная платформа для командных проектов: тимлид создаёт проект, приглашает студентов, ставит и назначает задачи; исполнитель начинает работу, а команда видит сохранённое состояние доски. Стек: FastAPI, PostgreSQL 17, HTML/CSS/JavaScript и Bootstrap 5.

Sprint 0 проектирования завершён. Эта папка содержит реализацию выбранного среза Sprint 1, **а не весь MVP**. Реализованы US-01, US-03, US-04, US-06, US-08, US-10, US-12, US-13, US-15 в описанных ниже границах. Полные Jira Acceptance Criteria требуют окончательной сверки команды; наличие кода само по себе не закрывает карточки.

Подробности: [docs/UI_COPY_VERIFICATION.json](docs/UI_COPY_VERIFICATION.json).

- Telegram OIDC Authorization Code + S256 PKCE: одноразовый state с привязкой браузера, nonce, RS256/JWKS и проверка claims; серверная cookie-сессия, CSRF/Origin и выход.
- Проекты и локальные роли: создатель — lead, участник другого проекта может оставаться student. Каждый объект проверяется через активное членство.
- Приглашение студента на семь суток: ссылка выдаётся при создании, в БД остаётся хеш. Ссылка принимается несколькими пользователями до отзыва; повтор не создаёт дубль и не повышает роль.
- Задачи с описанием, ожидаемым результатом, сроком и приоритетом; назначение, смена и снятие исполнителя; начало выполнения только текущим исполнителем.
- Пагинация доски, реальные поля и четыре согласованных состояния; доступный переход — `todo → in_progress`. ETag/If-Match защищают изменения: 428 без версии, 412 при устаревшей версии.

US-12 реализована срезом без доставки Telegram-уведомлений. Сдача/проверка результатов, комментарии, файлы, приглашение преподавателя, полный профиль, аналитика и ИСУ остаются дальнейшими задачами. Поздние колонки не заполняются фиктивными результатами. Production/dev-login обхода нет.

## Локальный запуск

Нужны Docker Desktop с рабочим Linux Engine и Python 3.12 для создания локального окружения. Команды выполняются из корня этой папки:

```powershell
python scripts/init_env.py
docker compose config --quiet
docker compose up --build --detach --wait
```

Initializer создаёт development `.env` с криптографически случайным hex-паролем PostgreSQL и пустыми Telegram credentials. Он не печатает пароль и никогда не перезаписывает существующий `.env`. Готовый файл остаётся локальным; `.env.example` содержит только пустой шаблон. Не выводите полную команду `docker compose config` в общий журнал: она подставляет секреты; используйте `--quiet`.

Приложение: [http://localhost:8000](http://localhost:8000). PostgreSQL не публикует host-порт. Приложение доступно только на `127.0.0.1:8000`; данные хранятся в отдельном томе Compose `eduproject_eduproject_pgdata`. При старте контейнер сначала применяет Alembic миграции, затем запускает Uvicorn с отключёнными access/query-логами. Если миграции не прошли, сервер не запускается. Контейнер приложения работает без root.

Остановка с сохранением данных: `docker compose down`. Перед будущими изменениями схемы и поставками команда должна подготовить резервную копию БД; удаление тома не входит в обычную остановку.

Без настройки Telegram страница входа показывает понятное сообщение, API возвращает `503 auth_not_configured`; фиктивная рабочая сессия не создаётся.

## Настройка настоящего Telegram-входа и production

В BotFather необходимо выбрать бота, открыть Login Widget и включить OpenID Connect Login. В Redirect URIs регистрируется точный адрес `https://ВАШ-ДОМЕН/api/v1/auth/telegram/callback`; полученные Client ID/Secret задаются в закрытом окружении. Используется [официальный Telegram OIDC flow](https://core.telegram.org/bots/telegram-login).

Production-настройки приложения по умолчанию требуют `APP_ENV=production`, `PUBLIC_ORIGIN=https://...` и `COOKIE_SECURE=true`. Локальный initializer создаёт только явно обозначенный development-режим с HTTP. Для production его не используют: владелец стенда отдельно настраивает домен, DNS, HTTPS reverse proxy, секреты и PostgreSQL. Hex-пароль удобно использовать в DSN без дополнительного URL-экранирования. Локальные HTTP cookies имеют другое имя; production использует `__Host-eduproject_session`.

Подробности API и переменных: [backend/README.md](backend/README.md). Интерфейс и последующая визуальная приёмка: [frontend/README.md](frontend/README.md).

## Повтор проверки

```powershell
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements-lock-dev.txt -r scripts/requirements-checks.txt
backend/.venv/Scripts/python.exe scripts/verify_all.py --postgres --require-postgres
```

В Linux вместо `Scripts/python.exe` используется `bin/python`. Нужен Node.js 24; npm-зависимостей у frontend нет, `npm install`/`npm ci` не нужны. Helper пишет новый набор в `qa/<дата-id>/`, отдельный backend-набор — в новый каталог `backend/qa/combined-<дата-id>/`; исходники и старые свидетельства не перезаписывает. Без Docker независимые тесты идут, PostgreSQL отмечается skipped; `--require-postgres` даёт ненулевой код, чтобы отсутствие проверки не выглядело успехом.

Полезные отдельные команды:

```powershell
backend/.venv/Scripts/python.exe -m unittest discover -s scripts/tests -v
backend/.venv/Scripts/python.exe scripts/check_structure.py
npm --prefix frontend test
backend/.venv/Scripts/python.exe -m unittest discover -s frontend/tests -p http_contract.py -v
```

В Windows sandbox TestClient требует разрешённого внутреннего socketpair/event loop. Это ограничение среды тестирования; запуск не заменяют фиктивным HTTP-ответом.

## CI и ручная поставка

`.github/workflows/ci.yml` запускается по pull request или вручную: Python 3.12, отдельный PostgreSQL 17 service, миграции, все backend/PG-тесты без пропусков, инфраструктурные проверки, Node/HTTP frontend-проверки и Docker build. Workflow сохраняет XML/TAP/HTTP-свидетельства. Actions закреплены проверенными commit SHA из [официальных release страниц GitHub Actions](https://github.com/actions/checkout/releases).

`.github/workflows/deploy.yml` запускается только вручную на выделенном Linux self-hosted runner с меткой `eduproject-deploy` и environment `eduproject-staging`. Потребуются защищённая default branch, ограничения/согласование GitHub environment и заранее установленный runner. У runner должны быть Docker Compose, Python 3.12 и переменные `EDUPROJECT_ENV_FILE` (абсолютный путь к production env вне checkout) и `EDUPROJECT_PUBLIC_URL` (тот же HTTPS origin, что `PUBLIC_ORIGIN`). `.env` для поставки допускает только переменные из таблицы backend и `POSTGRES_*`; пароль PostgreSQL — минимум 64 hex-символа.

Deploy script проверяет конфигурацию, выполняет `compose up --build --wait`, затем проверяет публичный HTTPS `/health/ready`. Без runner, окружения, работоспособной БД и подтверждённого HTTPS healthcheck успех не объявляется. Скрипты не создают хостинг, домен, сертификат или Telegram-бота; фактическая поставка остаётся внешним этапом.
